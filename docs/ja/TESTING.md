# TypeCT テスト仕様書 (TESTING)

本書は、`TypeCT` の品質保証方針、単体テスト・結合テストの構成、およびテストケース仕様書です。

---

## 1. テスト方針

`TypeCT` では、以下の3層でテストを実施します。

1. **単体テスト (Unit Tests)**:
   - 各モジュール（`legacy`, `model`, `input`, `tray`）の内部関数・メソッドの正当性を検証。
2. **結合テスト (Integration Tests)**:
   - `tests/integration_test.rs` において、旧バイナリファイルの読み込みからモデル更新、JSON永続化、日付ロールオーバーまでの一連の流れを結合検証。
3. **ドキュメントテスト (Doc-tests)**:
   - RustDoc 内に記述されたコード例が正しくコンパイル・動作することを検証。

## 2. テストケース一覧

### 2.1 旧バイナリパーサー (`legacy.rs`)
| No | テスト関数名                         | 検証内容                                                    |
| :- | :----------------------------------- | :---------------------------------------------------------- |
| 1  | `test_parse_valid_legacy_header`     | 正常な28バイトバイナリから7項目のu32値を正確にパースできるか |
| 2  | `test_parse_exact_28_bytes`          | ちょうど28バイトの境界値データがパースできるか              |
| 3  | `test_parse_insufficient_length`     | 27バイト以下の不足データに対し安全に `None` を返すか        |

### 2.2 データモデル & 永続化 (`model.rs`)
| No | テスト関数名                         | 検証内容                                                    |
| :- | :----------------------------------- | :---------------------------------------------------------- |
| 4  | `test_default_typect_data`           | 初期状態のカウンター値、記録日数、フラグが正常か            |
| 5  | `test_record_key_and_click`          | キーおよびマウスクリックの加算・時間帯配列反映が正確か      |
| 6  | `test_average_daily_keys`            | 記録日数に基づく1日平均打鍵数の計算ロジック（0除算防止含む）|
| 7  | `test_date_rollover`                 | 日付変更時に本日データが昨日へスライドしリセットされるか    |
| 8  | `test_save_and_load_json`            | JSONファイルへの保存と読み込みの完全往復テスト              |
| 9  | `test_try_import_legacy`             | 疑似data/data2からの取り込みおよび多重インポート防止        |
